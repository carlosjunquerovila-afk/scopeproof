# ScopeProof UX candidate — 16 October 2026

Base: ScopeProof 0.3.2. Product changes are isolated to `static/app.js` and `static/index.html`; no backend, provider or approval logic was changed.

## Findings and corrections

The evidence textarea and scope fields are editors for versioned records. In the base UI, loading the complete sample or typing a report does not save it. Analyze, review invitation, refresh and several other actions use saved values, then `show()` replaces editors from that saved record. This could silently erase edits and let a user prepare a draft with an older amount than the one typed in the scope editor.

The candidate adds persistent unsaved-report and unsaved-scope statuses, explicit discard actions, and disables actions that use/reload saved records until edits are saved or discarded. Report and scope can be saved separately; saving either preserves unsaved changes in the other. Controller guards prevent requests that would use the outdated saved record. Closing/navigation requests the browser's normal unsaved-change warning. Responses arriving after further typing preserve the newer editor content, including reverting to old text while a different version is being saved.

Independent review of the initial candidate identified three additional gaps: an older in-flight response could arrive after a newer save; text could be entered before the first state arrived; and scope edits needed the same protections as evidence. The corrected candidate serializes complete operations, blocking overlapping requests while permitting typing; the HTML and controller keep editors locked until state is available; and protection now includes milestone name, integer cents, currency and each criterion.

This does not implement autosave or claim protection for unsubmitted imported review JSON, local model settings, or any editor outside the report and scope. There is no multi-user collaborative editing implementation.
